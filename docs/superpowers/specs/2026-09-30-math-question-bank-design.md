# 数学考研题库网站设计

## 1. 目标

为个人整理数学分析和高等代数考研题，支持图片与 Markdown + LaTeX 录入，使用可编辑标签和细粒度知识卡片建立题目与定理之间的关系，并提供检索、复习和复盘闭环。

## 2. 用户与范围

- 第一版只服务单个用户，不包含应用内注册、登录和多人协作；部署访问由 Nginx Basic Auth 保护。
- 科目范围为数学分析和高等代数。
- 题目可以包含多张原题图片、文字题干、个人解法和参考解法。
- 标签由用户维护，知识卡片按单个定理、定义、引理、判别法或公式建立。

## 3. 核心概念

### 3.1 题目

题目保存题干、原题图片、科目、章节、解法、错误记录、掌握程度和复习日期。题目可以关联多个标签、多个知识卡片和多条复习记录。

### 3.2 标签

标签用于快速筛选。科目和章节使用结构化字段保存，掌握程度使用题目字段保存。用户可以创建方法、题型、来源和错误类型等自定义标签，并进行重命名、设置父标签、合并和归档。

### 3.3 知识卡片

知识卡片用于严谨解释单个知识点，字段包括名称、科目、章节、类型、正式表述、成立条件、证明、使用信号、常见错误、前置知识、相关题目和个人补充。知识卡片之间允许建立前置关系。

### 3.4 复习记录

每次复习单独保存时间、是否独立完成、可选耗时、遇到的问题、本次掌握程度和下次复习日期，不覆盖历史记录。

## 4. 用户流程

### 4.1 录入

上传题目图片或输入 Markdown + LaTeX，补充科目和章节，选择或新建标签，关联知识卡片，填写解法和错误记录。信息不完整时允许保存为草稿。

### 4.2 检索

网站打开后进入题目检索首页。支持关键词、科目、章节、标签、知识卡片、掌握程度、错误类型和是否到期复习等组合筛选。当前筛选条件清晰展示，并允许删除和保存常用筛选。

题目列表显示标题、科目、章节、知识点、标签、掌握程度、最近复习时间、下次复习时间和图片标识。题目详情页提供原题图片、文字题干、个人解法、参考解法、错误记录、关联知识卡片和复习历史。

### 4.3 复习

复习列表提供今天到期、最近做错和按知识点复习三个入口。复习时默认隐藏参考解法，用户完成思考后展开解法，记录本次结果并安排下一次复习。

复习间隔由本次复习结果决定：未完成 1 天，看提示完成 2 天，独立完成 7 天，熟练完成 30 天。间隔从复习当天计算。

掌握程度分为未开始、有思路但无法完成、可以完成但不稳定、熟练掌握。完整状态转移如下：

| 当前状态 | 未完成 | 看提示完成 | 独立完成 | 熟练完成 |
| --- | --- | --- | --- | --- |
| 未开始 | 有思路但无法完成 | 可以完成但不稳定 | 可以完成但不稳定 | 熟练掌握 |
| 有思路但无法完成 | 有思路但无法完成 | 可以完成但不稳定 | 可以完成但不稳定 | 熟练掌握 |
| 可以完成但不稳定 | 有思路但无法完成 | 可以完成但不稳定 | 熟练掌握 | 熟练掌握 |
| 熟练掌握 | 可以完成但不稳定 | 可以完成但不稳定 | 熟练掌握 | 熟练掌握 |

跳过不改变状态和下次复习日期。

### 4.4 知识归纳

从知识卡片可以查看所有关联题目，从题目可以进入关联知识卡片。第一版只保存前置知识关系，不强制建立完整知识树。

## 5. 页面范围

1. 题目检索首页
2. 新建和编辑题目
3. 题目详情
4. 知识卡片列表
5. 新建和编辑知识卡片
6. 知识卡片详情
7. 标签管理
8. 待复习列表
9. 简单统计页面

## 6. 视觉与交互方向

采用二次元学习桌面加角色陪伴式题库。主界面使用清晰、紧凑的学习工具布局，角色位于可折叠的侧边区域，只用于提示、进度反馈和轻量动画，不遮挡题目、证明和公式。颜色、字体、间距使用统一主题变量，角色素材和动画独立存放，便于后续更换。

## 7. 技术方案

- Django 单体应用
- Django 模板和少量 JavaScript 负责页面交互
- SQLite 起步，保留迁移 PostgreSQL 的可能
- MathJax 渲染 LaTeX
- 本地目录保存题目图片和附件
- 数据对象包括 Question、KnowledgeCard、Tag、ReviewRecord 以及题目与标签、题目与知识卡片的多对多关系

首版采用单用户、单管理员模式，不建立应用内注册页面和 Django 登录页面。Nginx Basic Auth 是首版唯一访问控制，保护所有管理页面、API 和媒体文件，凭据只存放在服务器受限权限的 htpasswd 文件中。Django 仍启用 CSRF 和会话机制，但不承担首版身份认证。本地开发通过环境变量 DEV_AUTH_BYPASS=true 显式关闭 Basic Auth，仅绑定 127.0.0.1；生产环境禁止该配置。后续增加账号系统时再迁移到 Django 用户模型。

## 8. 部署方案

目标环境为 Ubuntu 22.04。使用 Python 虚拟环境、Gunicorn、Nginx 和 systemd 运行服务，配置环境变量、数据库迁移、静态文件和 HTTPS。数据库文件与附件目录分开备份，初版提供数据库、图片和 Markdown/JSON 数据导出能力。

## 9. 初版明确不包含

- 多用户账号和公开分享
- 复杂 OCR
- 自动生成解答
- 复杂推荐算法
- 积分、等级、排行榜等复杂游戏化系统

这些功能等核心题库、知识关系和复习记录稳定后再评估。

## 10. 数据约束

- Question 正式保存时必须有科目、标题或题干至少一项；草稿允许全部为空，发布或完成编辑时执行正式题目校验。题干和解法允许为空。
- KnowledgeCard 必须有名称、科目和类型；正式表述允许为空，便于先建立待整理卡片。
- Tag 名称在同一父标签下唯一，归档标签不能用于新题目，但保留历史筛选结果。标签合并通过 redirect_to 字段保存目标标签，合并时压缩重定向链，历史查询解析到最终目标标签。
- 题目、知识卡片和标签使用稳定主键、created_at、updated_at；删除题目采用软删除，附件在确认无引用后清理。
- 题目附件单独建模，包含题目外键、文件路径、文件类型和排序字段，支持一题多图。
- 题目与标签、题目与知识卡片使用多对多关系并设置唯一约束。知识卡片前置关系禁止自引用、重复边和环。
- 掌握程度是 Question 的持久化字段，不作为标签存储。筛选器提供掌握程度条件，错误类型可以作为可编辑标签。
- 常用筛选保存为用户本地配置，记录筛选条件 JSON、名称和更新时间。
- 系统初始数据由 `seed_system_data` 管理命令创建，包含科目、常用章节和错误类型候选；命令可重复执行且不会产生重复记录。

## 11. 复习规则

ReviewRecord 一条记录对应一次题目复习，不代表多题会话。字段包括 question 外键、reviewed_at、result、mastery_before、mastery_after、duration_seconds 可空、note 文本和 next_review_at。批量复习由前端按题目逐条提交，未提交的题目不写入记录。

结果选项固定为：未完成、看提示完成、独立完成、熟练完成、跳过。提交后按以下规则更新 Question：

```text
未完成：掌握程度按状态表转移，间隔 1 天
看提示完成：掌握程度按状态表转移，间隔 2 天
独立完成：掌握程度按状态表转移，间隔 7 天
熟练完成：掌握程度设为熟练掌握，间隔 30 天
跳过：掌握程度不变，next_review_at 不变
```

首次复习前状态为未开始，因此首次独立完成后状态为可以完成但不稳定。状态转移以表格为准，复习间隔只根据本次结果决定。日期按服务器配置时区计算，默认使用 Asia/Shanghai。到期定义为 next_review_at 小于等于当天日期。最近做错定义为最近 30 天内结果为未完成或看提示完成的题目，列表按最近复习时间倒序并去重。逾期题目全部保留，按逾期天数倒序显示。

## 12. 搜索与关系维护

关键词搜索题目标题、题干、个人解法、参考解法和错误记录，大小写不敏感，第一版采用包含匹配。多个筛选条件使用 AND，同一字段的多个值使用 OR。结果分页，每页 20 条，默认按更新时间倒序。

标签合并将旧标签关系迁移到目标标签，保留旧标签的重定向记录。归档标签继续出现在历史题目中，但不出现在新建题目的默认候选中。删除知识卡片前必须处理题目关系和前置关系，默认只允许归档。

按知识点复习表示筛选关联该知识卡片的题目，再叠加到期、掌握程度或错误条件；知识卡片本身不单独保存掌握程度。

## 13. 安全、附件与渲染

- 所有管理页面、API 和媒体文件由 Nginx Basic Auth 保护；生产环境不允许匿名访问。本地开发只允许通过明确的 DEV_AUTH_BYPASS 配置并绑定 127.0.0.1。
- 开启 Django CSRF、防护性 Cookie 和生产环境 DEBUG=False；SECRET_KEY 从环境变量读取。
- 图片限制为 PNG、JPEG、WebP，校验 MIME、扩展名和文件大小，默认单文件不超过 10 MB。文件名使用随机 ID，媒体目录禁止执行脚本。
- Markdown 只允许安全的基础格式，过滤原始 HTML 和脚本。MathJax 只负责数学公式渲染，不执行用户脚本。
- Nginx 限制上传体积，媒体文件通过受保护路径访问。删除题目后清理无引用附件。

## 14. 导入、导出与备份

导出包包含版本号、题目、知识卡片、标签、关系、复习记录和附件目录。导入包中的稳定 ID 全部保留在独立命名空间中，导入前建立“包 ID到数据库 ID”的完整映射，再按映射写入所有外键关系。已存在同一稳定 ID的记录按更新时间更新，包内新记录生成新的数据库 ID并记录映射。导入前执行 schema 校验和关系校验，发现错误时整体回滚，附件按包内相对路径重新复制。

备份任务先暂停写入，执行 SQLite 一致性快照，再复制媒体目录并生成校验清单，最后恢复写入，确保数据库引用的附件存在于同一备份批次。每天生成一份加密压缩包，保留最近 14 份，并复制到离机存储。备份任务记录成功或失败，至少每月执行一次恢复演练。

## 15. 验收标准与测试

- 能创建带图片、LaTeX、标签和知识卡片关系的题目，并能编辑和删除草稿。
- 能按关键词、科目、标签、知识卡片、掌握程度和到期状态组合筛选，结果分页稳定。
- 能完成一次复习并生成 ReviewRecord，掌握程度和下次复习日期符合规则。
- 标签合并、归档和知识卡片归档不会丢失题目关系。
- 非法文件、超大文件和含脚本的 Markdown 被拒绝或清理。
- 导出包可以在空数据库中完整导入，导入失败时不产生部分数据。
- 测试覆盖复习状态变化、筛选组合、关系约束、上传校验、导入回滚和备份恢复。

## 16. Ubuntu 22.04 运行约束

- systemd 使用专用低权限用户运行 Gunicorn，项目目录和媒体目录归该用户所有，备份目录仅备份用户可读写。
- Nginx 负责 HTTPS、上传大小限制、静态文件和受保护媒体的 Basic Auth 转发；证书使用 Certbot 自动续期。
- SECRET_KEY、Basic Auth 文件路径和备份密钥通过受限权限的环境文件注入，不写入仓库。
- 应用日志和 Nginx 日志启用 logrotate，媒体目录禁止执行权限。
- SQLite 写入采用单 Gunicorn worker，避免多进程写锁；后续迁移 PostgreSQL 时再提高并发。

## 17. 统计口径

统计页面初版只提供固定指标：题目总数、各科目题数、各掌握程度题数、近 30 天复习次数、近 30 天错误结果次数、待复习题数。时间范围固定为近 30 天，空数据时显示 0 和空状态提示。
