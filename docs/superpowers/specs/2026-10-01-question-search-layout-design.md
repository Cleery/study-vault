# 题目检索页排版优化设计

## 目标

优化个人数学题库的题目检索页，使全部筛选条件集中在页面顶部，并让结果区域直接呈现完整题干和题目图片。页面继续保持现有二次元学习桌面风格，同时提高检索效率和长时间阅读的舒适度。

## 页面结构

页面顶部依次展示标题、题目总数和完整筛选面板。筛选面板分为四行：

1. 关键词搜索框，占据整行宽度。
2. 科目与章节。
3. 标签与知识卡片。
4. 掌握程度、到期状态和操作按钮。

筛选面板下方展示当前生效条件，并提供单项移除和清空全部入口。生效条件使用科目、章节、标签、知识卡片和掌握状态的真实名称，不显示数据库 ID。结果区域使用单列宽卡片，减少横向视线移动。

## 筛选面板

筛选条件保持全部展开。科目、章节、标签和掌握程度使用可换行的紧凑选择块，知识卡片使用便于扫描的多选控件。选中项通过背景色、边框和文字颜色共同表达状态。

主要操作为“应用筛选”和“清空全部”。保存筛选继续使用浏览器本地存储，保持现有最多保存 20 条的规则。提交筛选后页面定位到结果区域。

## 题目结果

每张结果卡片依次展示：

1. 科目和章节。
2. 题目标题。
3. 完整题干，使用现有安全 Markdown 与 MathJax 渲染。
4. 全部题目图片，保持原始比例并限制在卡片宽度内。
5. 标签、掌握程度和下次复习时间。
6. “查看详情”和“开始复习”操作。

个人解答、参考答案、错误记录和知识卡片正文只在对应详情页展示。结果卡片可以显示关联知识卡片名称，用于说明考察内容，不展示卡片正文。

## 视觉系统

筛选区使用白色纸张背景、细边框和轻阴影，通过留白和小标题划分分组。页面避免多层卡片嵌套。题干是结果卡片的主要视觉内容，辅助信息使用较小字号和较低对比度。

继续使用青绿色作为主要操作色，珊瑚色用于焦点和少量强调。掌握状态使用语义明确的颜色标识。所有文本保持正常字距，固定控件尺寸，防止选中状态导致布局移动。

## 响应式布局

桌面端筛选面板按行组织，每行内部使用响应式网格。移动端保持相同信息顺序，筛选项自动换行，按钮占据可触达宽度。图片宽度不超过结果卡片，使用浏览器原生延迟加载。长公式允许水平滚动，页面内容不得相互遮挡。

## 数据流与性能

现有查询参数、搜索服务和 URL 保持兼容。视图为结果查询增加附件预加载，并继续预加载标签和知识卡片。模板不触发逐题附件查询。

题干在视图层通过现有 `render_markdown` 处理，模板只输出清理后的 HTML。分页链接基于移除旧 `page` 参数后的查询字符串构造，防止重复页码参数。

## 空状态与降级

没有匹配结果时显示题目数量为零、简短提示和“新建题目”入口。没有 JavaScript 时，筛选提交、清空链接、分页和详情入口仍可使用。保存筛选、单项条件移除和提交后定位属于渐进增强。

没有附件时保持题目卡片紧凑，不显示空图片容器。单张图片加载失败时保留替代文字和详情入口，其他题目继续正常排版。筛选表单生成的查询参数继续由现有后端服务处理。

## 测试与验收

自动化测试覆盖：

1. 全部筛选条件位于顶部面板。
2. 完整题干经过安全 Markdown 渲染。
3. 题目全部图片按顺序展示。
4. 科目、章节、标签、掌握状态和复习时间正确显示。
5. 当前筛选条件可见，并存在清空入口。
6. 分页只包含一个 `page` 参数，同时保留其他筛选参数。
7. 空状态和无 JavaScript 核心流程可用。
8. 桌面与移动端结构不存在内容遮挡。

完成后运行检索页专项测试、完整测试、Django 检查和静态资源收集。若本机浏览器权限允许，再执行桌面与移动端视觉检查。
