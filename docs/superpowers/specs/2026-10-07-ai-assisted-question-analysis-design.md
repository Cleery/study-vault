# AI 辅助题目分析与知识卡片关联设计

## 1. 目标

在现有单用户数学题库中，保留题目图片和解答图片作为原始资料。用户完成题目后上传图片，系统通过可替换的 OpenAI 兼容模型进行文字识别、知识点提取、已有知识卡片匹配、标签建议和缺失知识卡片提醒。系统逐步提高自动化程度，高置信度结果可以自动保存，低置信度结果进入人工审核。

首版目标是跑通完整闭环：上传、识别、校对、分析、匹配、审核、保存。系统不得因为 AI 不可用而阻止题目和图片保存。

## 2. 范围与边界

### 2.1 首版包含

- 题目图片和解答图片多图上传
- 原图持久保存
- 题目与解答识别文本
- 识别文本手动校对
- 题目条件、目标、解题方法和候选知识点提取
- 已有知识卡片候选匹配及匹配依据
- 题型标签、方法标签和个人信号标签建议
- 缺失知识点的待建立卡片草稿
- 高置信度自动关联和低置信度审核
- 每次分析的状态、模型、原始响应和人工确认记录
- 中转站不可用时的失败状态和重新分析入口

### 2.2 首版不包含

- 自动生成并直接发布正式知识卡片证明
- 自动删除或合并已有知识卡片
- 无审核的低置信度自动关联
- 浏览器端保存 API Key
- 强制依赖某一家模型供应商
- 腾讯云普通服务器上的大型视觉模型本地部署

## 3. 用户流程

```text
上传题目图和解答图
  ↓
保存题目和原图
  ↓
创建 AI 分析任务
  ↓
视觉模型识别题目与解法
  ↓
用户校对识别文本
  ↓
提取条件、目标、方法和知识点
  ↓
检索已有知识卡片
  ↓
AI 对候选卡片重新排序并给出依据
  ↓
生成标签建议和待建立卡片建议
  ↓
高置信度自动保存，其他结果进入审核
```

### 3.1 页面区域

题目分析页分为四个区域：

1. 原始图片区：题目图、解答图、顺序、重新分析按钮。
2. 识别文本区：题目文本和解答文本，支持 Markdown、LaTeX、手动编辑和对照原图。
3. 知识点分析区：条件、目标、方法、候选卡片、置信度、匹配依据和操作按钮。
4. 个人想法区：触发信号、联想到的知识点和个人提示。

## 4. AI Provider 抽象

代码通过统一服务调用模型，题目录入页面不直接依赖供应商：

```python
analysis = ai_service.analyze_question(
    question_images=question_images,
    solution_images=solution_images,
    corrected_text=corrected_text,
    knowledge_cards=knowledge_cards,
    personal_notes=personal_notes,
)
```

首版提供 `RelayProvider` 占位实现。所有 Provider 必须返回经过字段校验的内部结构，模型原始文本不能直接写入业务字段。

服务器环境变量：

```env
AI_ENABLED=false
AI_PROVIDER=relay
AI_BASE_URL=https://placeholder.example/v1
AI_API_KEY=
AI_VISION_MODEL=placeholder-vision-model
AI_ANALYSIS_MODEL=placeholder-analysis-model
AI_TIMEOUT_SECONDS=60
AI_AUTO_LINK_THRESHOLD=0.90
AI_REVIEW_THRESHOLD=0.70
```

API Key 只存在服务器环境变量或受限权限配置文件中，浏览器不会接触密钥。

## 5. 内部分析结果

识别阶段保存：

```json
{
  "statement": "题目文字和 LaTeX",
  "solution": "解答文字和 LaTeX",
  "conditions": ["函数在闭区间上连续"],
  "goal": "证明存在零点",
  "recognition_confidence": 0.91
}
```

知识分析阶段保存：

```json
{
  "knowledge_points": [
    {
      "name": "介值定理",
      "matched_card_id": "已有卡片 ID",
      "confidence": 0.96,
      "reason": "闭区间连续、端点函数值异号，目标为证明存在零点"
    }
  ],
  "suggested_tags": [
    {"name": "连续函数", "category": "topic", "confidence": 0.91}
  ],
  "missing_cards": [
    {"name": "闭区间连续函数零点判定", "type": "theorem", "confidence": 0.74}
  ]
}
```

所有 JSON 必须通过服务端 schema 校验。解析失败时标记为分析失败，保留原始响应供排查，不能把不完整结果写入知识卡片或正式标签。

## 6. 知识卡片匹配

已有知识卡片的检索内容包括名称、正式表述、使用条件、证明、使用信号、标签和历史关联题目。系统先使用关键词和向量检索生成候选，再由 AI 结合题目条件、目标、方法和个人想法进行重排。

每个候选必须展示匹配依据：

- 名称或关键词命中
- 条件匹配
- 目标匹配
- 解法方法匹配
- 历史确认信息

系统不得静默覆盖用户已确认的关联。自动关联必须可以撤销并留下记录。

## 7. 标签与个人信号

标签建议分成三类：

- 题型标签：极限证明、矩阵秩、级数收敛
- 方法标签：夹逼、放缩、反证、构造辅助函数
- 个人信号：看到不等式、出现闭区间、出现参数

服务端标签类别枚举固定为 `topic`、`method`、`signal`。模型返回其他类别时，服务端拒绝该项并记录 schema 错误。正式标签按名称、规范化名称和类别去重，候选阶段保留同义词信息，用户确认后才写入正式集合。不同类别允许同名，检索结果显示类别以避免混淆。标签合并必须生成重定向关系，历史题目关联保持可追溯。

个人信号单独保存为结构化记录：

```text
触发信号：看到闭区间和连续函数
联想到：介值定理
个人提示：先检查端点函数值是否异号
```

自动生成的标签初始为建议状态，用户可以确认、编辑、忽略或合并。候选标签不能直接进入正式标签集合。

## 8. 置信度和审核规则

```text
置信度 >= 0.90：自动关联已有知识卡片，提供撤销
0.70 <= 置信度 < 0.90：显示候选，等待确认
置信度 < 0.70：进入待审核列表
```

每次分析最多返回 10 个知识点候选和 20 个标签候选。置信度只用于当前分析中的排序和审核分流，服务端记录模型给出的原始分数与最终人工结果，不把模型分数当作统计意义上的校准概率。并列候选全部进入审核，模型明确返回无合适候选时不自动创建关联。

同一题目同一分析版本只允许一个生效结果。重新分析创建新的分析版本，旧结果保留为历史记录。只有最新版本且输入指纹与当前校对文本一致时，才允许写回自动关联和建议。用户已经确认或拒绝的结果优先级高于后续模型建议，重复关联必须幂等。

缺失知识点只生成待建立卡片草稿，包含名称、类型、来源题目和识别依据。正式表述与证明需要用户确认后再发布。

## 9. 数据状态和失败处理

分析状态：

```text
待分析、分析中、待校对、待确认、已完成、失败
```

失败场景包括 API 超时、供应商错误、图片格式不支持、模型返回格式错误和候选卡片检索失败。失败时保留题目、图片、手动文字和错误信息，支持重新分析。AI 调用不能阻塞普通保存。

每次分析记录供应商、模型名称、时间、输入摘要、原始响应、候选结果和用户最终选择，方便重跑、审计和统计确认准确率。

分析任务使用题目锁和版本号控制并发。重复点击、超时重试和队列重复投递都通过任务唯一键去重。旧版本任务完成后不得覆盖新版本校对文本或新版本分析结果。状态迁移必须允许失败后重试，重试生成新分析版本并保留失败原因。

隐私策略：原始图片和识别文本只对已通过网站认证的用户可见；原始模型响应默认保存 30 天，分析摘要和人工确认结果长期保存；API Key 不写入数据库、HTML、JavaScript 或普通日志；发送给外部 Provider 的内容只包含当前题目图片、校对文本、必要的知识卡片候选和个人想法；部署文档需要记录 Provider 的数据保留和训练政策。后续可增加手动删除分析原始响应的入口。

## 10. 分阶段实施

实施优先级严格按最小闭环推进。第一阶段不引入向量数据库、复杂异步队列或自动创建正式关联，先使用 Django 数据库中的关键词候选和同步模拟 Provider 跑通页面与状态机。真实视觉接口、后台任务和向量检索分别在后续阶段加入。每一阶段都保持题目图片、手动文字和已有知识卡片功能可独立使用。

### 阶段一：占位流程

- 增加环境配置读取
- 增加 Provider、schema 和服务抽象
- 增加分析记录和状态
- 增加模拟 Provider
- 增加识别文本校对页面
- 增加候选结果审核页面
- 只实现单题分析、关键词候选和固定模拟响应
- 暂不启用真实自动关联，所有建议进入审核

### 阶段二：真实中转站

- 接入 OpenAI 兼容视觉接口
- 上传图片并保存识别文本
- 加入超时、限流和重试
- 加入知识卡片候选检索
- 加入标签和缺失卡片建议
- 使用后台任务执行真实调用，增加超时、重试和任务唯一键
- 先使用关键词检索，确认稳定后再评估向量检索

### 阶段三：自动化提升

- 根据确认历史调整阈值
- 增加相似卡片和重复标签检测
- 增加标签合并建议
- 增加旧题重新分析
- 增加模型结果对比
- 在有足够人工确认记录后，再启用高置信度自动关联

## 11. 验收标准

- AI 关闭时，题目和图片仍可保存。
- 占位 Provider 可以返回固定模拟结果，页面能完整展示并审核。
- 图片识别文本可以手动修改，修改后再进行知识点分析。
- 已有卡片候选显示置信度和匹配依据。
- 高置信度结果自动关联，低置信度结果不会静默写入。
- 未匹配知识点可以一键创建待建立卡片草稿。
- 标签建议支持确认、编辑、忽略。
- AI 调用失败后可以重新分析，原题数据不丢失。
- API Key 不出现在 HTML、JavaScript、日志或数据库普通展示页面中。
- 每次分析可以追溯模型、时间、原始响应和人工确认结果。
- 题目分析任务具有唯一键，重复提交不会产生重复关联或覆盖较新的校对文本。
- 旧分析版本完成后不能写回新分析版本，重分析结果与历史结果可以区分。
- `topic`、`method`、`signal` 之外的标签类别会被 schema 校验拒绝。
- Provider 超时、Provider 错误、schema 解析失败和候选检索失败均会进入 `失败` 状态，题目原图、校对文本和既有关联保持不变。
- 图片无效时不会创建分析任务，确认标签后才会写入正式标签集合。
- 置信度阈值、候选数量、重复关联和无合适候选规则都有自动化测试覆盖。
