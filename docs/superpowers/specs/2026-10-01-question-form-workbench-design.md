# 新建题目图片工作台设计

## 目标

优化新建与编辑题目页面，使图片录题成为主要工作流，同时保留完整的 Markdown、LaTeX、解答、标签和知识卡片编辑能力。

成功标准：

1. 用户可以通过快速模式完成科目、标题、题干和题图录入。
2. 用户可以在完整模式中补充解答、掌握程度、标签和知识卡片。
3. 新图片与已有图片可以统一删除和排序。
4. 文字、选项和待上传图片可以保存到浏览器本地草稿。
5. 页面在无 JavaScript 环境下仍可完成基础表单提交。
6. 页面延续现有题库自习室视觉风格，并适配桌面、平板和手机。

## 本期范围

### 包含

1. 快速录入与完整编辑两种界面模式。
2. 图片上传、粘贴、多选、预览、删除和拖动排序。
3. 编辑已有题目时管理历史附件。
4. Markdown 和 LaTeX 编辑工具栏。
5. 使用现有安全 Markdown 渲染器生成实时预览。
6. IndexedDB 本地草稿保存、恢复和放弃。
7. 完整编辑中的题目、解答、关联三个标签页。
8. 响应式布局、键盘操作和状态提示。

### 暂不包含

1. OCR 和数学公式识别服务。
2. 图片裁剪、旋转和标注。
3. 多用户协同编辑。
4. 服务器端定时自动保存。

OCR 入口保留为禁用状态，并显示后续开放说明。本期不建立无实现能力的后端接口。

## 页面结构

### 顶部区域

页面标题下方提供“快速录入”和“完整编辑”分段控制。切换只改变字段呈现，不重置表单值。

快速录入默认启用，页面主体为图片工作台：

1. 左侧为题图工作区，占据主要宽度。
2. 右侧为基础信息区，包含科目、标题、题干、草稿状态和保存操作。
3. `980px` 以下改为单列，题图工作区位于基础信息区上方。

### 图片工作区

上传区支持文件选择、拖放和剪贴板粘贴。新附件支持 PNG、JPEG、WebP，并继续使用现有图片校验规则。

选中图片后显示固定比例缩略图。每个项目包含：

1. 图片序号和文件名。
2. 拖动手柄。
3. 删除按钮。
4. 可访问的图片说明。

完整图片使用 `object-fit: contain`，不得裁切题目内容。OCR 按钮保持禁用，并显示后续开放状态。

历史数据中可能存在 `document` 和 `other` 类型附件。工作台必须显示这些附件，使用文件图标、文件名和类型代替图片预览，并允许删除与排序。统一顺序覆盖题目的全部附件类型。OCR、图片放大和缩略图只对图片类型启用。

### 基础信息区

快速模式显示：

1. 科目。
2. 标题。
3. 题干。
4. 图片附件。
5. 保存状态。
6. 保存草稿、保存题目和取消操作。

题干编辑器提供常用 Markdown 与 LaTeX 插入按钮，包括粗体、行内公式、块级公式、求和、极限、分式和上下标。按钮只插入标准文本语法，用户始终可以继续手动编辑。

### 完整编辑标签页

完整模式提供三个标签页：

1. 题目：科目、章节、标题、题干、附件和当前草稿状态。
2. 解答：个人解答、参考解答、错误记录和掌握程度。
3. 关联：标签和知识卡片。

标签和知识卡片使用可搜索的多选控件，并保留原生 `select multiple` 作为无 JavaScript 回退。章节选项根据科目在浏览器中过滤，服务器继续执行跨科目关系校验。

保存意图只由提交按钮决定，不再提供会产生冲突的 `draft` 复选框：

1. `save_intent=draft` 将题目保存为草稿。
2. `save_intent=publish` 将题目保存为正式题目。
3. 新建页面分别显示“保存草稿”和“保存题目”。
4. 编辑草稿时分别显示“保存草稿”和“发布题目”。
5. 编辑正式题目时，草稿按钮显示“转为草稿”并要求确认，正式按钮显示“保存修改”。
6. 校验失败后，视图将提交意图放回上下文，页面保持相同按钮语义和模式。

## 渐进增强

页面服务端输出完整表单。JavaScript 启动后再应用模式切换、标签页、拖动排序、预览和本地草稿。

无 JavaScript 时：

1. 所有完整字段按语义分组依次显示。
2. 原生多文件输入可上传多张图片。
3. 原生多选控件可选择标签和知识卡片。
4. 表单校验、保存和取消保持可用。
5. 已有附件使用 `remove_attachment` 复选框标记删除。
6. 每个未删除已有附件提交必填的 `attachment_position_<id>` 非负整数。
7. 位置重复、缺失、负数或非整数时拒绝提交；合法位置按数值排序后归一化为连续序号。
8. 新文件在无 JavaScript 请求中按 multipart 顺序追加到全部未删除已有附件之后。
9. 无 JavaScript 环境中，表单校验失败后浏览器不会保留文件输入，页面必须明确提示用户重新选择新文件。

## 实时预览

新增一个只处理预览的 POST 端点。浏览器以防抖方式发送当前题干 Markdown，服务端调用现有 `render_markdown()`，返回经过清理的 HTML。

预览流程：

1. 用户输入题干。
2. 浏览器等待短暂空闲时间后发送 CSRF 保护请求。
3. 服务端返回安全 HTML。
4. 浏览器替换预览内容，并请求 MathJax 对新增内容排版。
5. 新输入出现时取消尚未完成的旧请求，避免响应顺序覆盖最新内容。

预览请求失败时保留最近一次成功结果，并显示非阻塞错误状态。正式保存仍由普通表单 POST 完成。

## 附件排序协议

增强后的附件列表使用重复隐藏字段 `attachment_order` 提交统一顺序。每项使用稳定令牌：

1. 已有附件：`existing:<attachment-id>`。
2. 新图片：`new:<file-index>`。

浏览器通过 `DataTransfer` 保持文件输入中的新文件顺序，并同步隐藏顺序字段。服务端必须验证：

1. 所有已有附件属于当前题目。
2. 令牌没有重复或未知值。
3. 新文件索引位于上传列表范围内。
4. 删除列表只包含当前题目的附件。
5. 顺序列表恰好包含每个未删除已有附件一次。
6. 顺序列表恰好包含每个新上传文件一次。
7. 标记删除的已有附件不得出现在顺序列表中。

只要请求包含一个 `attachment_order` 字段，就采用增强协议并执行完整集合校验。JavaScript 初始化后额外提交固定隐藏字段 `attachment_protocol=enhanced`，用于表示增强协议的空队列，此时允许没有任何 `attachment_order` 字段。请求同时不含顺序字段和该协议标记时，采用无 JavaScript 协议。两种协议不能在同一次请求中混用。

保存过程在数据库事务中执行。为避免 `question + sort_order` 唯一约束在交换位置时冲突，已有附件先移动到高位临时顺序，再按最终列表写入连续顺序。新附件按最终位置创建。标记删除的附件只在整个表单验证成功后删除。

数据库事务无法自动回滚已经写入文件存储的新文件。附件服务必须记录本次请求创建的每个存储名称，并采用以下生命周期规则：

1. 数据库事务成功提交后保留新文件。
2. 附件创建、排序或事务提交失败时，对本次新文件执行尽力清理，并再次确认数据库中没有同名引用。
3. 旧附件只在数据库成功提交后通过现有 `transaction.on_commit` 清理。
4. 存储删除失败时记录包含文件名和异常的错误日志，不掩盖原始表单或事务异常。
5. 增加只读预览默认开启的孤儿附件清理管理命令。命令比较存储路径与数据库引用，只处理超过安全时间阈值的文件；实际删除需要显式参数。

新建题目继续使用相同顺序协议，只包含 `new:<file-index>` 令牌。

## IndexedDB 草稿

本地草稿使用 IndexedDB，避免 `localStorage` 无法保存图片文件的问题。

数据库包含一个 `drafts` 对象存储，并为 `target_key` 与 `updated_at` 建立索引。每个浏览器标签页首次打开表单时生成随机 `editor_session_id` 并保存在 `sessionStorage`，刷新页面继续使用同一标识。记录键为：

1. 新建页面：`question:create:<editor-session-id>`。
2. 编辑页面：`question:<question-id>:<editor-session-id>`。

每条记录包含：

1. 文本、选择项、复选框和当前界面模式。
2. 新图片的 Blob、文件名、媒体类型和最后修改时间。
3. 图片令牌顺序与待删除已有附件列表。
4. 活动标签页。
5. 单调递增的草稿修订号、保存时间和表单版本号。
6. 编辑页面加载时的题目 `updated_at` 与已有附件 ID、类型、顺序签名。
7. 用于发现历史草稿的 `target_key`，值为 `question:create` 或 `question:<question-id>`。

输入变化后采用防抖保存。页面通过 `target_key` 索引查询当前目标的全部历史会话草稿，并按更新时间列出。用户可以恢复指定草稿、删除指定草稿或开始空白会话。在用户明确选择前不覆盖服务器表单值。新建页面允许保留多个独立题目的草稿。

页面使用 `BroadcastChannel` 执行会话占用检测。新页面声明 `editor_session_id` 后等待同标识页面响应；检测到复制标签页或并发占用时生成新的随机标识，并将原草稿复制为新会话记录后再写入。频道不可用时使用带过期时间的 `localStorage` 租约作为降级方案。页面关闭不删除 IndexedDB 草稿，过期租约不得阻止后续恢复。

编辑草稿的服务器基线与当前题目或附件签名不一致时进入冲突状态。冲突状态允许恢复文本、选项和新图片，不自动恢复旧附件删除与排序操作；用户也可以放弃本地草稿并使用服务器版本。

原生表单提交前，JavaScript 必须立即完成一次 IndexedDB 写入，再携带本次草稿修订号与提交意图继续提交。校验失败后，重新加载的表单按同一会话和修订号自动恢复新图片 Blob、图片队列、模式和活动标签页；服务端回填文字字段保持优先，避免覆盖服务端校验后的值。

成功重定向页面带有短期成功标记。同一标签页从 `sessionStorage` 读取待确认的草稿键和修订号，只在 IndexedDB 当前记录仍为该修订号时清除。较新的草稿不会被旧提交清除。处理后立即从地址中移除成功标记。

用户点击取消时不自动删除草稿。IndexedDB 不可用、配额不足或写入失败时显示状态提示，用户确认后仍可提交；此时明确提醒校验失败可能需要重新选择新图片。

## 并发编辑保护

编辑页面输出签名后的 `question_version` 隐藏字段。签名载荷包含：

1. 题目 ID 与 `updated_at`。
2. 全部附件的 ID、`updated_at`、类型、文件名与顺序。
3. 当前标签 ID 集合。
4. 当前知识卡片 ID 集合。

编辑 POST 在数据库事务中通过 `select_for_update()` 锁定题目，然后重新计算当前版本并与已签名载荷比较。所有编辑入口都使用同一服务。版本不一致时拒绝字段、关系和附件写入，返回冲突状态，并保留本地草稿。

冲突页面提供“加载服务器版本”和“保留当前内容为本地草稿”。用户重新加载后可以从新基线恢复文字、选项和新图片；旧基线上的附件删除与排序保持禁用，直到用户重新确认。页面不提供静默强制覆盖。

## 服务端边界

`QuestionForm` 继续负责题目字段、图片格式与科目章节关系校验。附件排序与删除解析放入独立服务函数，避免将事务和文件生命周期逻辑堆入模板或视图。

建议边界：

1. 表单：字段值和上传文件校验。
2. 附件服务：令牌解析、所有权校验、删除与排序。
3. 视图：协调表单、数据库事务、消息和重定向。
4. 模板：输出语义分组和渐进增强钩子。
5. JavaScript：模式、标签页、文件队列、预览和 IndexedDB 草稿。
6. 版本服务：生成签名版本、锁定题目、比较字段与关系基线。

新建与编辑页面共享同一模板和前端控制器。附件服务同时覆盖两个入口。

## 错误处理

1. 表单字段错误显示在对应字段旁，并在页面顶部提供错误摘要。
2. JavaScript 可用时，提交前等待当前草稿修订持久化；校验失败后从该修订恢复模式、标签页和浏览器文件预览。
3. 附件令牌无效时拒绝整次提交，不执行部分删除或排序。
4. 预览失败只影响预览区域。
5. IndexedDB 失败只影响自动草稿，并提供明确状态。
6. 图片验证错误需要显示文件名与具体原因。
7. 删除已有附件前校验题目所有权。
8. 新文件回滚清理失败需要记录日志，并可通过孤儿清理命令处理。
9. 编辑版本冲突返回明确状态，不执行任何字段、关系或附件写入。

## 可访问性

1. 所有字段保留可见标签。
2. 模式控制和标签页使用原生按钮及正确的 ARIA 状态。
3. 图片删除按钮包含文件名或序号。
4. 拖动排序同时提供键盘上移、下移按钮。
5. 草稿、上传和预览状态使用 `aria-live="polite"`。
6. 校验错误摘要获得焦点，并链接到对应字段。
7. 移动端操作目标保持足够尺寸，长文件名可以换行。

完整模式标签页遵循 WAI-ARIA 标签页键盘模式：

1. 标签列表使用 `role="tablist"`，每个标签使用 `role="tab"`、`aria-controls`、`aria-selected` 和 roving `tabindex`。
2. 左右方向键移动并激活相邻标签，`Home` 与 `End` 移动到首尾标签。
3. 面板使用 `role="tabpanel"` 与 `aria-labelledby`。
4. JavaScript 初始化时自动激活包含第一个服务端校验错误的标签页。
5. 点击错误摘要链接时先激活目标字段所在面板，再将焦点移到字段。
6. 无 JavaScript 时所有面板保持可见，错误链接直接聚焦字段。

## 视觉规范

页面沿用现有青绿色、珊瑚色、纸张色和学习助手。工作区保持紧凑、安静，避免页面区块堆叠成多层卡片。

1. 主要操作使用青绿色。
2. 删除和错误状态使用克制的珊瑚红。
3. 图片工作区使用浅色背景与虚线上传边界。
4. 表单区域圆角不超过 8px。
5. 完整模式标签页保持稳定高度，切换时不改变顶部布局。
6. 数学预览允许长公式水平滚动。

### 服务端测试

1. 新建题目上传多张图片并保持顺序。
2. 编辑题目删除、追加和交换图片顺序。
3. 伪造其他题目的附件 ID 时拒绝提交。
4. 重复令牌、未知令牌、遗漏令牌、删除与排序冲突和越界新文件索引被拒绝。
5. 表单验证失败时不删除已有附件。
6. 新文件写入后发生数据库失败时执行存储清理，清理失败会记录日志。
7. 旧文件只在事务提交后删除。
8. 图片格式和大小校验继续生效。
9. 图片、文档和其他历史附件在统一顺序中不会冲突或丢失。
10. 无 JavaScript 位置字段的合法、重复、缺失和非法输入得到确定处理。
11. 保存意图正确控制草稿状态，校验失败后保持意图。
12. Markdown 预览清理脚本与危险属性，并保留 MathJax 分隔符。
13. 孤儿清理命令默认只预览，显式删除只处理超过阈值且无数据库引用的文件。
14. 无 JavaScript 表单字段和附件控制可用。

### 前端模板契约测试

1. 模式控制、标签页、上传区、草稿恢复区和状态区域存在。
2. 图片队列提供删除、拖动和键盘排序钩子。
3. JavaScript 使用 `URL`、`DataTransfer`、IndexedDB 和请求取消机制。

### 浏览器行为测试

使用 `pytest-django` 的实时测试服务器和 Playwright Chromium 无头模式。Playwright 只作为开发测试依赖，不进入生产依赖。

1. 两个新建标签页获得不同会话键，复制标签页检测占用后派生新键。
2. 关闭标签页后，新页面可以发现、选择和删除历史草稿。
3. 刷新页面保持当前会话键和草稿修订。
4. 两个编辑页面依次提交时，第二次旧版本提交进入冲突状态且不改写数据库。
5. 服务器基线变化时不恢复旧附件删除与排序操作。
6. 提交操作等待 IndexedDB 事务完成后才发出请求。

8. 成功重定向只清除相同修订，保留更新后的草稿。
9. IndexedDB 不可用和配额错误不会阻止用户确认后继续提交。
10. 键盘可以完成标签页切换、图片上移下移和删除。
11. 初始错误标签页自动激活，错误摘要链接会先切换面板再聚焦字段。

### 手工视觉检查

1. 桌面双栏和窄屏单列没有横向溢出。
2. 图片保持完整且缩略图布局稳定。
3. 长公式、长标题和长文件名不会遮挡其他内容。
4. 标签页、对话区和错误摘要可以通过键盘操作。
5. 深浅主题下文字、边界和状态具备足够对比度。

## 部署影响

本功能不增加数据库模型和生产依赖。开发环境增加 Playwright 浏览器测试依赖。Ubuntu 22.04 生产部署流程保持不变。实时预览使用现有 Django 应用，IndexedDB 数据只保存在当前浏览器。
